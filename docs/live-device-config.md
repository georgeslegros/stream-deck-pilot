## How to read a tile (schema v2 recap)

Each tile is an icon + two text zones, with layout declared explicitly:

- **`iconPlacement`** — `corner` (small icon, top-left; used for value tiles) or
  `center` (large centred icon; used for toggles / navigation).
- **`center`** zone — the large hero text. `template` is resolved from live MQTT
  (`{value}`/`{unit}`/`{label}`); split on the first space → big value + small unit.
- **`bottom`** zone — a small caption (here, a static room / sensor name).
- **`rules`** — ordered, first-match-wins over the extracted **numeric** value; a match
  sets `backgroundColour` and may override the icon. Colour ink (light/dark) is automatic.
- **`gestures.Tap`** — `Publish` (emit MQTT) or `Navigate` (switch page).

Two layout families are in use:

| Family | iconPlacement | center | bottom | Example |
|--------|---------------|--------|--------|---------|
| Value tile | `corner` | `{value} {unit}` (or live `{label}`) | room/sensor name | CO₂, temperatures, humidity, climate |
| Toggle / action / nav | `center` | — | caption (or none) | lights, vacuum, Pi-hole, setpoints, arrows |

## Colour rules (per tile family)

| Family | Condition → colour |
|--------|--------------------|
| CO₂ | `>1000` → `#E74C3C` red · `>700` → `#E67E22` orange · `>=0` → `#27AE60` green |
| Temperature | `>23` → `#E67E22` orange · `>=19` → `#27AE60` green · `>=0` → `#2980B9` blue |
| Humidity | `>70` → `#2980B9` blue · `>=40` → `#27AE60` green · `>=0` → `#E67E22` orange |
| Light | `==1` → `#E0B432` + `lightbulb` · `==0` → `#3A3A3A` + `lightbulb-outline` |
| Vacuum | `==1` → `#6C3483` + `robot-vacuum` · `==0` → `#2E4053` + `power-plug` |
| Pi-hole | `==1` → `#1E8449` + `shield-check` · `==0` → `#784212` + `shield-off` |
| Climate display | `>=25` → `#E74C3C` · `>=22` → `#E67E22` · `>=0` → `#2980B9` |
| Setpoint ± | `>=0` → fixed (`#27AE60` for `+`, `#E74C3C` for `−`) |

> Conditions are numeric only. State-driven tiles (lights/vacuum/Pi-hole) therefore
> carry a numeric `value` of `1`/`0`; their on/off icon comes from the matched rule.

## Data flow (Home Assistant ↔ deck)

**Inbound (sensor → tile).** HA automations publish **retained** JSON to the topics
above on each entity state change. Mosquitto redelivers retained values to the deck's
wildcard subscription on (re)connect, so tiles repopulate after a restart.

| Topic | HA entity | Payload |
|-------|-----------|---------|
| `home/office/co2` | `sensor.alpstuga_air_quality_monitor_carbon_dioxide` | `{value:int, unit:"ppm"}` |
| `home/office/temperature` | `sensor.alpstuga_air_quality_monitor_temperature` | `{value:1dp, unit:"C"}` |
| `home/office/humidity` | `sensor.alpstuga_air_quality_monitor_humidity` | `{value:int, unit:"%"}` |

## Notes

- Numeric formatting: whole numbers render with no decimal (`772 ppm`, `46 %`),
  fractional values keep one decimal (`23.8 C`); climate cur/tgt is integer (`22/18`).
- Only the **active** page is projected to the hardware; off-page MQTT updates update
  desired state and paint on navigation.
- Empty keys (`main` key 9; `climate` keys 3, 4, 8, 13, 14) are intentionally undefined —
  the renderer clears keys absent from the destination page on navigation.
